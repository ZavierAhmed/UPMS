# P3.2C dependencies — cheque lifecycle still proposed

P3.2B3 does not add cheque posting, clearing, dishonour or correction. Integrated cheque payments remain blocked; custody is nonspendable. A future-dated receipt must never automatically credit cash or UBL.

Approve instrument identity, drawer/payee, dates, custody/deposit/clearance/dishonour/cancellation, duplicate references, partial/multiple instrument policy and accounting recognition first. Resolve legacy immediate client-credit-on-receipt history without a second party credit. Opening custody value is not an instrument register or recognized bank balance.

The new full cash/bank refund policy cannot be reused to infer cheque settlement. Dishonour, cancellation, returned instrument and actual bank refund are different events. Preserve originals and link canonical lifecycle events; recognize spendable money only on approved clearance. Reversal of already recognized money and any client/vendor adjustment must be one authorized atomic transaction. A cheque-funded expense must retain category/employee snapshots and prove recognized funding. Erroneous entries and metadata corrections still need independent policy.

Purchases/goods returns remain separately blocked pending available-stock, consumed/sold quantities, historical rates, supplier evidence, payable credit versus refund and tax rules. A vendor credit, goods return or challan return is not proof of incoming cash.

Design new canonical tables/guards/recovery version only if needed, starting from 29/72 and preserving every existing definition. Extend protected off-host collection and genuine independent restore before hosted migration. Test duplicate/concurrent instruments and claims, sufficient funds, role/password/CSRF/stale requests, every applicable posting failure, exact dated reports and authenticated recovery. This plan authorizes no hosted work.
