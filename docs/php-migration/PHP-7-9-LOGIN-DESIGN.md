# PHP-7.9 login design

The active Simple V1 login now uses a balanced desktop two-panel composition: approved Unique Plastic logo, charcoal branding panel, orange accents and original static packaging shapes on the left; Welcome back, Sign in to UPMS, labeled fields and an orange submit action on the right. No stock photograph, unrelated identity, registration or fake password-reset flow was added.

At widths up to 680px it becomes one clean panel, retaining logo and staff-access label while removing decorative art and long branding copy. Controls remain touch-sized; seven actual browser widths cover 320, 360, 390, 414, 768, 1024 and 1440px with no overflow. Inputs are stacked within the form on desktop and mobile. A stronger, scoped CSS rule prevents inherited generic business-form grids/buttons from overriding the login design. Keyboard tab order, visible focus, show/hide password labels and aria-pressed are checked.

The native submit handler still performs the existing CSRF acquisition and Laravel login. The new component only receives onSubmit/busy/error; it does not implement authentication. Pending authentication displays Signing in… and disables resubmission. Invalid credentials and session expiry have safe, clear messages. Correlation/internal detail is not displayed on the login card.

Business-record loading is rendered only for authenticated users outside the forced password-change state. The business-read context is also gated to that state, preventing a stale route/read flag from disabling signed-out controls. This fixes the false Loading records banner after logout and keeps login responsive. Successful login triggers the existing authorized data-loading effect; all API endpoints, cookies, permissions, passwords and expiry rules are unchanged.

Actual browser checks cover incorrect password, password visibility, a held real login request proving pending state, successful login and logout. A separate real-UI expiry test expires only the new synthetic session, clicks Refresh dashboard, verifies the safe login message/enabled controls/no false record loading, then successfully signs in again through fresh CSRF. The existing security acceptance additionally expires a synthetic server session and checks rejection, CSRF/origin, Secure/HttpOnly/Strict host cookies, CSP/frame/no-store policy and static/error responses. No unsafe-inline, CDN, external font/auth provider or bypass was introduced.
