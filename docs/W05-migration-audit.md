## Behaviors to preserve

- Program.cs composes host/security middleware before API boundary, static allowlist, rate limiter and route fallback. WeatherForecast is a leftover sample controller, not used by the public website; assess before removal. Development OpenAPI is tooling only.
- ProductionHosting.cs requires explicit hosts; refuses trust-all forwarded headers. Only exact configured peer IPs may supply the nearest forwarded client IP and scheme; forwarded host is ignored. HTTPS redirect 307, HSTS 180 days on HTTPS, nosniff, DENY, referrer/permissions policies, production CSP without inline scripts/styles. Compress website/assets, never customer API responses.
- PublicWebsite.cs loads the build manifest and 11 prerendered documents at startup, fails if absent or unsafe. Exact case-sensitive public routes, optional trailing slash, GET/HEAD; known page other methods 405, unknown page 404 HTML/noindex. API, management, admin, private prerender documents and file-shaped paths never receive SPA HTML. Only assets/licenses/icons/favicon are public static resources; immutable hashed assets, one-hour other static cache, licenses noindex. HTML/robots/sitemap no-cache.
- Runtime canonical origin must be a public DNS HTTPS origin with no path, credentials, custom port, query or fragment and must be an allowed host. Unconfigured origin yields no canonical/og:url, noindex HTML, robots disallow-all and sitemap 503. Configured sitemap enumerates only the route registry. Preserve titles, descriptions, Open Graph and meaningful initial HTML.
- InquiryApi.cs: POST /api/v1/public/inquiries, case-insensitive API matching and trailing slash. All API responses receive generated 32-hex correlation header, no-store and structured errors `{code,message,correlationId,errors:null|object}`. Unknown APIs and unsupported inquiry methods fall through to JSON 404. Boundary checks origin and Sec-Fetch-Site before media type/size. No CORS. Only application/json without content encoding, 16 KiB limit including chunked input, JSON max depth 8. Nonzero D-format UUID idempotency key. Normalize null/missing strings and trim; reject wrong JSON types, honeypot and invalid fields.
- InquiryValidation.cs: required customerName 100, email 254, phone 40, productCategory 30; optional companyName 150, quantity/capacity 80; message 10–4000. Reject controls except message CR/LF/tab. Plain mailbox email, phone punctuation plus 7–20 ASCII digits. Categories exactly buckets/cans/jars/containers/custom. Preserve field messages.
- Fixed window per-client rate limit: default 5 requests per 10 minutes, clamp 1–100, no queue, 429 JSON plus Retry-After. Boundary failures do not consume permits; parsed/validation/duplicate attempts do.
- InquirySubmissionService.cs: SHA256 normalized payload fingerprint, canonical UUID key, concurrent requests share one promise/reference; conflict 409, 1000-entry capacity 503. Completed entries expire after 30 minutes; pending work cannot be evicted. Cache every outcome including unavailable/unknown. Disconnect does not trigger another delivery; bounded 1–30 second timeout and shutdown cancellation produce conservative unknown. Process-local only, no durable/exactly-once claim.
- ConfiguredInquiryDelivery.cs: Disabled default. DevelopmentFile only in Development, atomic private local outbox, explicit development_saved response. Production requires complete SMTP credentials/addresses, mandatory StartTLS or TLS-on-connect. Fixed company subject/from/to, validated customer Reply-To, plain text only, no CC/BCC. smtp_accepted confirms relay acceptance only; unavailable 503, explicit rejected 502, uncertain 503 with reference. Disconnect failure after acceptance does not undo acceptance. Never log payloads, SMTP exceptions or secrets; only outcome/reference/correlation.
- React/Vite build-time prerender implementation, route registry, all public source assets and React Router retained. Vite's .NET certificate/proxy integration must be replaced for Node development; no visual changes needed.
- Existing xUnit InquiryApiTests/WebsiteTests and Vitest frontend tests provide baseline. Run .NET baseline before removing projects, recreate coverage in Node and record parity evidence. Historical documentation/assets remain.
