# Proposed P3.2C — cheque lifecycle after the expense extension

No cheque posting or lifecycle was introduced in P3.2B2. With money integration enabled, cheque receipts and integrated payment reversals remain blocked. CHEQUE_CUSTODY is not spendable and a future-dated receipt must never credit UBL/cash automatically. Disabled-money mode retains the existing legacy behavior truthfully.

Approve instrument identity, drawer/payee, dates, custody/deposit/clearance/dishonour, cancellations, partial/multiple instruments, duplicate references, correction evidence and reconciliation first. Resolve how earlier immediate client-credit-on-receipt history transitions without creating a second party credit. Cheque custody opening value is not an instrument register or bank balance.

Only an approved clearance event may recognize spendable bank funds. Dishonour/cancellation must link and preserve the original instrument, client/vendor history and actual recognized money effects in one transaction. Future cheque-funded business expenses must retain category/employee snapshots and an actual recognized spendable source, not infer funding from a cheque label or custody value.

If instrument state needs new tables/guards, prepare another canonical versioned migration and recovery format on top of **29 tables / 72 guards**. Extend off-host backup/independent restore before any hosted migration, preserve current employee/category/master histories and all existing guard definitions, and test duplicate/concurrent instruments, correction limits, insufficient funds, permissions, exact reporting and recovery. This plan is not a hosted readiness or activation approval.
