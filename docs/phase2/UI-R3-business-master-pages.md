# Dedicated master pages and read-only API review

Before implementation, reviewed the existing master manifest/list/write adapters and SQL permissions. Customers, vendors and items share existing masterService and tables; writes retain its canonical validation, idempotent coordinate transaction, version checks and audit. Dedicated pages reuse MasterForm, never a duplicate registry. Existing item category/base unit/four dimensions are immutable from creation and will be locked in the editor, with exact values retained in submissions. No stock/opening field is editable.

Reviewed additive read-only endpoint: GET /business/masters/:resource/:key, limited to customers/vendors/items. Calls the existing identity.read with the resource's unchanged read permission, validates the positive numeric key and returns an explicit allowlist of existing approved master metadata (no finance, hashes, credentials, balance initialization or writes).404 for missing/unsupported records and403 for a missing resource permission. This supports a true deep-linked detail beyond the100-row list bound. No migration or new grant. Authorization and successful reads will be tested against the isolated real SQL schema and ordinary roles. Product stock uses existing inventory/overview?q=code only when inventory.read is present; unauthorized users get metadata only. Financial links appear only with existing ledger/read permissions.

Routes: /customers, /vendors, /products (under /management), /new, /records/:id, /records/:id/edit. /customer-ledgers is separate; legacy /sales/customers remains a ledger bookmark. /masters remains the reference workspace; dedicated registries have visible links and no dependence on discovering a dropdown option.

## Verified outcome
Three directories implement list/search/add/detail/edit and history navigation. Real isolated browser checks create and revise all three using original commands; canonical product fields remain locked and stock remains read-only. The additive metadata GET passed an extra real SQL permission/field-allowlist test alongside the original16 business assertions. No financial records or opening balances are created by master editing.
